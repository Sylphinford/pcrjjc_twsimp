# pcrjjc_twsimp

公主连结 **台服**（tw.sonet.princessconnect）竞技场查询与自动推送插件，运行于 HoshinoBot。

插件只处理台服，

插件内部按 uid 首段自动分流到对应的登录账号。

主要特点：

- **账号零配置**：把游戏的 `playerprefs.xml` 丢进 `account/` 就算完成，不用手填 udid / 密码
- **分区独立队列**：台一与台二/三/四 使用各自的登录账号与优先级队列，一边出问题不拖累另一边
- **自动推送**：jjc、pjjc、排名上升、上线提醒四类通知，按账号单独开关
- **版本号自维护**：台服 `APP-VER` 从 App Store / Google Play 自动抓取并本地缓存，游戏更新后无需改代码
- **自带自检**：`check_account.py` 可以在不启动 bot 的情况下定位账号文件问题

## 一、环境要求

| 项目 | 要求 |
|---|---|
| Python | 3.8 及以上 |
| 框架 | HoshinoBot（nonebot 1.x） |
| 数据库 | SQLite（由 `sqlmodel` + `aiosqlite` 自动创建，无需手动建库） |
| 前置插件 | [multicq_send](https://github.com/SonderXiaoming/multicq_send) |

`multicq_send` 只负责把图片发出去（普通群聊、私聊通知都走它），放在 `modules` 目录即可，

## 二、安装

### 1. 放置插件

把整个 `pcrjjc_twsimp` 文件夹放进 HoshinoBot 的 `modules` 目录，最终路径形如：

```
hoshino/modules/pcrjjc_twsimp/__init__.py
```

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 确认 hoshino 配置

`hoshino/config/__bot__.py` 中：

```python
MODULES_ON = {
    'pcrjjc_twsimp',
    'multicq_send',
}
SUPERUSERS = {123456789}   # 管理员 QQ，用于负载查询等管理指令
```

`SUPERUSERS` 至少要有一个，否则管理员指令无法使用，私聊推送申请也不会推送给管理员。

## 三、准备台服账号

### 1. 取出账号文件

登录台服客户端后，从设备中取出：

```
/data/data/tw.sonet.princessconnect/shared_prefs/tw.sonet.princessconnect.v2.playerprefs.xml
```

有 root 直接复制；没有 root 可用备份工具或 `adb backup` 取出。
将此文件复制到插件的 `account/` 目录，多个账号就重命名成不同文件名：

```
account/
├── tw_main.xml      # 台一账号
├── tw_alt.xml       # 台二/三/四账号
└── README.md
```

后缀必须保持 `.xml`（大小写均可，`.xml.txt` 不会被读取）。

> 仅支持新版 playerprefs（加密格式）。旧版本或已损坏的文件解析不出字段，会被明确跳过。

### 2. 为什么要准备两个账号

台服四个区的玩家数据是分开的，查询只能由**同区账号**发起。插件内部分两条线：

| 登录账号所属区 | 能查询的 uid |
|---|---|
| 台一（uid 首位为 `1`） | 台一玩家 |
| 台二 / 三 / 四（uid 首位为 `2`/`3`/`4`） | 对应区的玩家（同一个账号即可，二三四共用一条线） |

建议 `account/` 里至少放一个台一账号 + 一个台二/三/四账号。
缺哪一边，那一边的 uid 查询就会被忽略（日志会给出警告）。

### 3. 先自检，再启动

在插件目录下执行：

```bash
python check_account.py
```

输出示例：

```
账号目录：.../pcrjjc_twsimp/account
  找到 2 个 xml：

  · tw_main.xml
      [√] viewer_id = 1234567890   区服：台一·美食殿堂
          UDID = a1b2...9f0e   SHORT_UDID = 1234...7890
  · tw_alt.xml
      [√] viewer_id = 2345678901   区服：台二·真步真步王国

结果：2 个账号可用
  台一与台其他都有账号，配置完整。
```

## 四、配置项

### 代理 `client/proxy.json`

台服接口在部分网络环境下需要代理，不配置会表现为登录失败 / 查询超时：

```json
{
    "proxy": {
        "http": "http://127.0.0.1:7890",
        "https": "http://127.0.0.1:7890"
    }
}
```

不需要代理就保持 `{"proxy": {}}`。修改后需重启 bot。

### 私聊推送上限 `var.py`

```python
class BaseSet(Enum):
    tw_max_pri = 0   # 允许申请私聊推送的人数上限，0 表示不允许申请
```

### 其他

- 数据库文件由 `database/dal.py` 自动生成在插件目录下，删除即等于清空所有绑定
- `img/frame.json` 记录每个 QQ 选择的头像框，首次运行自动创建

## 五、启动验证

启动 bot 后，正常日志应当包含：

```
读取台服账号：viewer_id=1234567890（美食殿堂）← tw_main.xml
读取台服账号：viewer_id=2345678901（真步真步王国）← tw_alt.xml
账号表刷新完成，共 2 个台服登录账号
当前台服 APP-VER = 5.9.0
加载账号：ID1234567890, 服务器：台服-1区
加载账号：ID2345678901, 服务器：台服-2区
账号登录完成：2/2 个可用，台一队列=已启动，台其他队列=已启动
自动推送启动状态：台一队列=已就绪，台其他队列=已就绪
```

对照排查：

| 日志 | 含义 / 处理 |
|---|---|
| `未在 ... 找到任何 .xml 账号文件` | `account/` 为空或路径不对，跑一次 `check_account.py` |
| `账号文件 xxx 解析不出 [...]` | 文件不是 playerprefs 或被截断，重新取一次 |
| `没有读到任何台服账号，自动推送无法启动` | 全部文件都失败，自动推送不会运行 |
| `未绑定台其他服务器的查询账户` | 缺台二/三/四账号，这些区的 uid 会被忽略 |
| `APP-VER 获取失败` | 网络不通且本地无缓存，见「七、两个细节」 |
| `账号 xxx 初始化失败，已跳过` | 单账号异常，其他账号继续工作，按 traceback 排查 |

## 六、指令

### 查询

| 指令 | 说明 |
|---|---|
| `竞技场帮助` | 输出帮助图（管理员会额外看到管理员指令） |
| `竞技场查询 [uid]` / `竞技场查询 @某人` | 查自己绑定的全部账号；带 uid 或 @ 则查对方 |
| `详细查询 [uid 或 序号]` | 输出完整档案图 |
| `深域查询 uid1 uid2 ...` | 可一次查多个 uid，结果合并成一张图 |
| `竞技场订阅状态 [@某人]` | 查看订阅开关状态，@ 省略为查自己 |
| `竞技场记录 [序号]` / `击剑记录 [序号]` | 当天排名变化记录 |
| `查询竞技场订阅数` | 本群已订阅的 uid 总数 |

### 绑定

| 指令 | 说明 |
|---|---|
| `竞技场绑定 uid [昵称]` | 每人最多 8 个；只绑 1 个时序号可省略 |
| `删除竞技场绑定 序号` | 序号必填 |
| `清空竞技场绑定` | 清除自己的全部绑定 |
| `竞技场修改昵称 序号 新昵称` | — |

### 订阅设置

| 指令 | 说明 |
|---|---|
| `竞技场设置 开启/关闭 jjc` | 其余同理：`pjjc`、`排名上升`、`上线提醒` |
| `竞技场设置 1110 [序号]` | 四位开关，详见下节 |
| `在本群推送` | 推送发到当前群（群内发送，无需加好友） |
| `换私聊推送` | **私聊**发送，改为私聊推送，受 `tw_max_pri` 限制 |

### 头像框

| 指令 | 说明 |
|---|---|
| `更换头像框 文件名` | 别名：`竞技场换头像框`、`更换竞技场头像框` |
| `查询头像框` | 别名：`查竞技场头像框`、`查询竞技场头像框` |

可选文件即 `img/img/frame/` 下的图片（`color.png`、`gold.png`、`silver.png` 等），
文件名写错时机器人会直接列出全部可选值。

### 管理员（需 SUPERUSER）

| 指令 | 说明 |
|---|---|
| `pcrjjc负载查询` | 群聊 / 私聊用户数、绑定数、昨日与今日推送次数 |
| `pcrjjc删除绑定 QQ号` | 删除该 QQ 的全部绑定 |
| `pcrjjc关闭私聊推送` | 一次性关闭所有私聊推送 |

> 绝大多数指令仅限群聊使用，只有 `换私聊推送` 需要在好友私聊里发。

## 七、两个细节

### 「竞技场设置 1110」怎么读

四位数字依次对应四类通知，`0` 关闭、`1` 开启：

| 位置 | 含义 |
|---|---|
| 第 1 位 | jjc 排名变化 |
| 第 2 位 | pjjc 排名变化 |
| 第 3 位 | 排名上升提醒（对 jjc 与 pjjc 同时生效） |
| 第 4 位 | 上线提醒（`0`~`3` 四档） |

上线提醒的四档：

| 值 | 冷却 | 播报时间 |
|---|---|---|
| `0` | — | 关闭 |
| `1` | 10 分钟 | 仅每日 14:30 ~ 14:59（当日重置前） |
| `2` | 10 分钟 | 全天 |
| `3` | 1 分钟 | 全天 |

等级越高推送越频繁，`3` 适合盯上线但容易被刷屏，建议按需使用。

示例：`竞技场设置 1110 2` 表示第 2 个绑定开启 jjc、pjjc、上升提醒，关闭上线提醒。

### APP-VER 是怎么来的

台服每个请求都必须带 `APP-VER`，版本号错了服务器会直接拒绝（表现为登录失败或查询报错）。
取值顺序在 `client/tw_pcrclient.py` 的 `get_ver()`：

1. 进程内缓存（6 小时有效）
2. App Store 台区接口 `itunes.apple.com/lookup?bundleId=tw.sonet.princessconnect&country=tw`（JSON，最稳）
3. Google Play 页面，用正则抓 `[[["5.9.0"]],[[[36]]]` 中的版本号（与页面语言无关）
4. 本地缓存 `client/tw_ver.txt`（上一次成功的值）
5. `DEFAULT_APP_VER` 常量兜底

补充：

- 资源版本 `RES-VER` 无需手动维护，启动用默认值，之后按响应里的 `required_res_ver` 自动更新
- 长期运行的 bot 在重连时会刷新 `APP-VER`，游戏更新后不必重启
- 若所有在线来源都不可达，改 `DEFAULT_APP_VER` 应急即可

## 八、自动推送机制

- 启动时重建账号表并登录，随后启动 `query_loop`：一轮查完所有绑定，**间隔 180 秒**进入下一轮
- 台一与台二/三/四 各自一个优先级队列，互相独立，一边卡住另一边照常推送
- 服务器维护时（`服务器在维护`）按服务器返回的时间休眠，不会刷屏报错
- 单次查询失败会重试，重试仍失败只写日志，不影响后续 uid
- 成员退群 / 被踢时自动删除其在本群的绑定，避免往空群推送

## 十、常见问题

**Q：绑定后查询没反应，日志提示「已自动忽略」？**
A：`account/` 里缺对应区服的登录账号。台一玩家需要台一账号，二/三/四玩家需要二/三/四账号。

**Q：查询报「位数不对」？**
A：台服 uid 固定 10 位，首位是区服编号（1 美食殿堂 / 2 真步真步王国 / 3 破晓之星 / 4 小小甜心）。

**Q：账号文件明明放进去了，还是读不到？**
A：先跑 `python check_account.py`。常见原因是扩展名变成 `.xml.txt`、放错目录、文件被截断，或不是新版加密格式。

**Q：换了账号文件需要重启吗？**
A：需要。账号表只在启动时重建。

**Q：能多人同时查询吗？**
A：可以，查询走优先级队列，自动推送优先级最低，手动查询会插到前面。

**Q：推送太频繁 / 太吵？**
A：用 `竞技场设置 关闭 排名上升` 之类的指令逐项关闭，或用四位开关一次性设置。

**Q：`换私聊推送` 提示「已达上限」？**
A：管理员把 `var.py` 里的 `tw_max_pri` 调大，或改用 `在本群推送`。

**Q：修改了头像框图片？**
A：把新图放进 `img/img/frame/`，玩家用 `更换头像框 文件名` 选择即可，无需重启。

**Q：详细查询里「公主骑士RANK」显示「未知」？**
A：`rank_exp.csv` 缺失或损坏。补回文件后无需重启，下一次查询会自动重新加载；
启动日志里也会有一行 error 明确提示，其余字段不受影响。
